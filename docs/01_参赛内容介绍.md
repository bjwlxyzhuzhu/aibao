## 二、作品背景

实践基地园共 16 个班（小班 8、中班 4、大班 4），教职工 60 余人，按"园长—副园长—中层—职能室—班级"四级架构管理。日常保教管理中有三个反复出现的问题：

1. **巡查难闭环。** 入园、进餐、盥洗、午睡、户外、离园等一日生活环节靠园长和保教人员人工巡查，记录散落在纸本和微信里，发现的问题没有统一的整改单、时限和验收，整改常常没人跟进。
2. **家园沟通耗人。** 家长反复询问作息、食谱、请假、入园须知，教师下班后还在回消息；措辞稍有不当就可能引发投诉。
3. **园务决策听不全。** 调整作息、修订制度时，保健、教师、家长、安全几方的意见难以在一次讨论里摆全，分歧容易被忽略。

通用大模型可以帮忙"写"，但直接让单个模型下结论存在两个风险：一是会误判（把通风需要的半拉窗帘当成问题），二是会出风险（向家长做出越权承诺或给出医疗建议）。幼儿园场景还要求幼儿的照片、姓名、健康信息不外泄。本作品针对这些约束设计。

## 三、设计目的

- 用**对抗**给 AI 判断纠错、防风险：诊断员与一线质询员辩论、裁判员必须引用条款才能裁定；红队审查员攻击发给家长的草稿。
- 用**协同**支撑多视角决策和整改闭环：四个视角智能体交叉质询、综合员保留分歧出简报；整改单按岗位自动建议责任人并计时升级。
- **人始终在回路中**：AI 的结论、整改单、决策简报一律是"AI 草稿"，由园长确认后才生效；安全、卫生、健康类问题和低置信度结论 100% 进入园长复核；教师可对任何结论申诉。
- **隐私优先**：所有云端模型调用必须经过园内脱敏网关，网关失败即拒发。

## 五、核心功能（对应评分项：研发设计 15 分）

### 5.1 总体设计

系统由 **四个端、三条链、12 个智能体** 组成（架构图、工作流图见《03_系统架构与工作流图》）：

| 链 | 参与智能体 | 设计要点 |
| --- | --- | --- |
| ① 保教巡查链（主线） | 调度官爱宝 → 巡查诊断员星宝 ↔ 一线质询员护苗 → 条款裁判员明理 → 整改跟踪员小步 | 诊断—质询—答辩最多两轮；裁判每条必须引用知识库切片，引用不存在自动改判"待人工"；安全/卫生/健康类与置信度 < 0.7 的条目强制进园长复核 |
| ② 家园沟通链 | 调度官爱宝 → 爱宝答疑员 ↔ 风险审查员小卫士（红队） | 只用公开知识库；涉及具体孩子即转人工；红队按隐私、越权承诺、医疗建议、情绪、事实五类攻击草稿；低风险发送，中风险由爱宝按审查意见用大模型改写一次再审，高风险转教师 |
| ③ 园务议事链 | 保健小医、教师小师、家长小家、安全小盾 → 决策综合员爱宝 | 第一轮各自陈述，第二轮每方至少质疑一方；简报必须保留分歧，不替园长下结论 |

| --- | --- | --- | --- |
| 调度官 | 爱宝（红橙醒狮凤凰） | 识别输入类型、路由、权限检查、留痕 | flash |
| 巡查诊断员 | 星宝 | 对照条款从照片与文字中找问题 | max |
| 一线质询员 | 护苗 · 小熊 | 站在一线教师角度反驳或补充情境，防误判 | flash |
| 条款裁判员 | 明理 · 猫头鹰 | 必须引用条款才能裁定，给出置信度 | max |
| 整改跟踪员 | 小步 · 小乌龟 | 起草整改单、计时、提醒、升级 | flash |
| 爱宝答疑员 | 爱宝 | 依据公开知识起草家长回复 | flash |
| 风险审查员（红队） | 小卫士 · 柴犬 | 攻击式审查家长回复草稿 | max |
| 保健视角 | 小医 · 小白兔 | 卫生、健康、营养风险 | flash |

每个智能体职责单一、输出固定 JSON 结构，后端用 pydantic 校验，不合格自动重试；系统提示词版本化管理（见《02_提示词体系文档》）。

### 5.3 贴合园所真实组织的业务设计

- **岗位 + 数据范围鉴权**：按园方真实四级架构预置 19 个岗位；班级岗位按学期生效，巡查与整改按"发生时的任职"归属，换岗不串数据；教师个人数据只有园长可见，不做排名。
- **校历与单双周课表**：按校历周次（而非日期推算）判断单双周，正确处理国庆跨假期合并周；巡查时自动预选环节并带出当时在岗的班级教师或专任教师。
- **工单时限与两级升级**：按园所工作时间计时（跳过周末、夜间、校历外假期），时限过半提醒，超时一级升级到班长/部门负责人和副班长，再超时二级升级到分管副园长和园长；可申请延期一次。升级只发提醒，不改变责任人，不自动追责。
- **整改责任人按岗位建议**：设施→后勤处，膳食→伙管室，卫生消毒→保健室，进餐/午睡/盥洗→当期保育岗，其余→当期班长；园长可改。

## 六、用户体验（对应评分项：用户体验 15 分）

- **教师端三步提交**：选班级（默认本人任职班）→ 拍照/语音/文字 → 提交；系统按当前时间和作息表预选环节，带出在岗教师；提交前可预览人脸打码效果。
- **过程可见、可申诉**：教师能看到诊断、质询、裁判的完整对话和引用的条款原文，对任一结论可一键申诉，申诉直接进园长复核。
- **3D 议事桌**：智能体以原创卡通形象围坐议事桌，实时显示发言气泡、质询/支持/引用光束、裁定托盘和置信度环，支持导演镜头和事后回放；对抗过程不再是黑箱。
- **园长驾驶舱**：环节 × 16 班问题热力图、闭环率、对抗前后误判率、超时工单、家长端统计、待办提醒；真实数据与演示数据分开显示，可切换。
- **家长端"爱宝答疑"**：亲切口吻、80 字以内、标注依据来源；涉及孩子个案即回复"已转给老师"。
- **管理员初始化向导与导入中心**：园方用一张 xlsx 模板导入教职工、班级任职、校历、作息、课表，系统给出红/黄/绿校验报告，确认后写入，每次导入可整体回滚。
- **诚实标注**：未接入大模型或调用失败时，界面明确标注"离线规则引擎"；AI 生成的整改单、周报、简报均标注"AI 草稿，经园长确认"。

教师、园长与家长的使用反馈见第九部分 9.3。

## 七、技术实现（对应评分项：技术实现 15 分）

| 层 | 选型 |
| --- | --- |
| 前端 | React 18 + Vite + TypeScript + Tailwind；react-three-fiber + drei（three.js）实现 3D 议事桌；手机端自适应 |
| 后端 | Python + FastAPI + SQLAlchemy；智能体编排自写（不依赖低代码平台）；SSE 实时推送对抗过程 |
| 数据 | PostgreSQL 16 + pgvector（开发环境可用 SQLite） |
| 知识库 | PyMuPDF / python-docx 解析 PDF、Word，按"章—条"切片并保留条款号；字二元组 BM25 检索，预留向量检索 |
| 脱敏网关 | 文字：教职工姓名字典→代号、幼儿姓名→编号、手机号/身份证/住址→占位、体温等健康明细→类别；图片：YuNet 人脸检测 + 高斯模糊，去 EXIF（含 GPS） |
| 语音 | 本地 SenseVoice-Small + FSMN-VAD（CPU 可跑），音频不出园 |
| 大模型 | 通义千问 qwen3.8-max（诊断、裁判、红队、综合）与 qwen3.8-flash（其余）；每个智能体的模型可在管理端单独切换 |
| 部署 | Docker Compose：db、api、asr、web（Nginx），园方现有 HTTPS 反代 |

关键技术保障：

1. **网关在类型层面不可绕过**：大模型客户端只接受网关生成的 `RedactedPayload` 类型，未经网关的数据无法发出；图片未经打码直接拒发；每次调用记录脱敏前后对比（管理员可查）。
2. **引用可验证**：裁判引用的切片编号由后端到知识库核对，不存在即强制"待人工"，防止模型编造条款。
3. **结构化输出与容错**：所有智能体输出 JSON，pydantic 校验失败重试；模型调用失败重试，仍失败则该条转人工或降级为离线规则引擎，不阻塞其他条目。
4. **全程留痕**：每一轮发言写入 `agent_messages`，同时驱动 3D 实时演示和回放；每次模型调用记录模型、耗时、token。
5. **端到端测试**：`api/tests/test_smoke.py` 覆盖校历单双周、人脸模糊、对抗与条款引用、强制复核、发往模型的文字无教职工姓名、申诉→复核→整改下发（非园长不能下发）→回传→验收、家长端转人工与红队拦截、议事链简报、导入校验与回滚、知识库上传后可检索。
6. **参赛代码包自动去密钥**：`scripts/export_package.py` 排除 `.env`、数据库、上传文件和含真实姓名的园方模板，扫描到疑似密钥即中止。

## 八、创新性（对应评分项：创新性 25 分）

1. **"对抗—协同"双机制按风险分工。** 不是所有环节都多智能体：会犯错的判断（巡查结论）用"诊断 ↔ 质询 → 裁判"的对抗纠错；会出风险的输出（家长回复）用红队攻击；需要多视角的决策（园务议事）用四方协同加交叉质询。
2. **"对抗降低误判"可量化。** 系统同时保存"诊断员单独判断"和"对抗后裁定"两套结果，以园长复核为标准答案，自动计算两者各自的误判率，驾驶舱实时展示。这让"多智能体是否真的有用"成为可检验的问题，而不是口号。
3. **条款强约束的裁判。** 裁定必须引用本园知识库条款切片，后端核验编号真实存在；不能引用就只能交人工。
4. **代表一线教师的质询员。** 专门设置站在一线教师立场的智能体，为被巡查者"说话"、补充情境（如替岗、通风需要），减少对教师的误判和对立情绪。
5. **议事简报保留分歧。** 综合员被要求明确写出"哪两方在哪一点上有分歧"，不得抹平，也不替园长下结论。
6. **3D 议事桌把对抗过程可视化。** 光束、表情、置信度环让园长和教师看懂 AI 是怎么得出结论的，并可事后回放。
7. **私有化 + 脱敏网关的隐私架构。** 业务数据、原始照片、语音都留在园内，只有脱敏后的文字和打码图片发往云端模型。

- 系统不做大模型微调或训练；园长和教师提供的经验范例只进入知识库，使用前签书面同意书。
