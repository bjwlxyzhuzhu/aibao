# 爱宝保教智囊团 · 分步构建说明

> 本说明分两部分：第一部分是"如何从零构建这个多智能体系统"（设计与开发步骤，供评审了解构建过程）；第二部分是"如何在一所幼儿园部署并投入使用"（供复现与推广）。
> 命令均可在源代码包根目录执行。源代码包由 `python scripts/export_package.py` 导出，已排除密钥、数据库和含真实姓名的园方模板。

---

## 第一部分 构建过程

### 步骤 1 梳理问题与边界

1. 访谈园长与保教人员，确定三个要解决的问题：巡查难闭环、家园沟通耗人、园务决策听不全。
2. 先划定"不做什么"：不做模型微调和训练；不处理幼儿照片、声音、健康明细；不让 AI 直接派任务或下结论；不对接学籍、收费等业务系统。
3. 确定合规底线：私有化部署 + 脱敏网关；所有 AI 输出是"AI 草稿，经园长确认"。

### 步骤 2 设计智能体分工与"对抗—协同"机制

1. 按"会不会犯错、会不会出风险、需不需要多视角"给每个环节选机制：
   - 巡查判断会犯错 → 诊断员 ↔ 一线质询员对抗，条款裁判员裁定；
   - 家长回复会出风险 → 红队审查员攻击草稿；
   - 园务决策需要多视角 → 保健、教师、家长、安全四方协同 + 交叉质询，综合员出简报。
2. 为每个智能体定义单一职责、默认模型档位（max / flash）和固定 JSON 输出结构（见《02_提示词体系文档》）。
3. 设计卡通形象：爱宝、星宝沿用园方吉祥物，其余 8 个智能体为原创动物形象（`assets/avatars/`）。

### 步骤 3 搭建工程骨架

```text
api/   FastAPI 后端（agents 编排、gateway 脱敏网关、kb 知识库、importer 导入中心、services 校历/工单、routers 接口）
web/   React 18 + Vite + TypeScript + Tailwind + react-three-fiber（四个端 + 3D 议事桌）
asr/   本地语音识别容器（SenseVoice-Small + FSMN-VAD）
deploy/ nginx.conf、install.sh
```

1. `docker-compose.yml` 定义 db（PostgreSQL 16 + pgvector）、api、asr、web 四个服务。
2. 编写大模型连通测试（管理端"模型与阈值 → 连通测试"，接口 `POST /api/admin/llm/test`），确认 OpenAI 兼容接口、图片输入方式。

### 步骤 4 组织架构、岗位权限与导入中心

1. 预置四层组织架构、19 个岗位、16 个班与班级岗位模板（大班 / 中小班）。
2. 鉴权按"岗位 + 数据范围"：兼岗取并集；班级岗位按学期生效，巡查和整改按发生时的任职归属。
3. 导入中心：一张 xlsx 模板含教职工名单、班级任职、校历周次、作息时段、特色课表；上传后生成红/黄/绿校验报告（重名、岗位不在清单、班级缺人、一人跨两班等），确认后写入，每次导入保存快照，可整体回滚。导入的教职工姓名自动进入脱敏字典，初始密码随机生成、首次登录强制修改。
4. 校历按周次判定单双周（处理国庆跨假期合并周），据此取单双周课表，推算某时刻的环节和在岗教师。

### 步骤 5 脱敏网关（先写测试）

1. 文字（`api/app/gateway/redact_text.py`）：教职工姓名字典 → 教职工代号；幼儿姓名 → 编号；手机号、座机、身份证号、住址 → 占位符；体温等健康明细 → 类别。
2. 图片（`api/app/gateway/redact_image.py`）：YuNet 人脸检测，全部人脸高斯模糊，去 EXIF；原始件与打码件分目录存放，上传后先给教师预览。
3. 网关出口（`api/app/gateway/__init__.py`）：只产出 `RedactedPayload`；大模型客户端（`api/app/llm/client.py`）只接受该类型；图片不在打码目录直接拒发；每次调用写脱敏日志。
4. 测试：含人脸照片必须全部模糊；发往模型的文字中不得出现任何教职工姓名。

### 步骤 6 知识库

1. 上传 PDF / Word（`.doc` 经 LibreOffice 无头模式转换）→ 按"章—条"切片并保留条款号（`api/app/kb/__init__.py`）。
2. 知识分"内部"与"公开"两类：家长端只检索公开知识。
3. 检索用字二元组 BM25；`llm/client.py` 已预留 embedding 接口，实测 embedding 模型后可叠加向量检索。

### 步骤 7 智能体基类与三条链

1. 基类（`api/app/agents/base.py`）：读取 `prompts/*.md` 及版本号 → 经网关 → 调模型 → pydantic 校验（失败重试）→ 每轮发言写入 `agent_messages`。未配置模型或调用失败时降级为离线规则引擎（`offline_rules.py`），运行记录标注 `offline`，界面显示"离线规则引擎"。
2. 巡查链（`inspect_chain.py`）：检索 8 条条款 → 诊断 → 质询 → 答辩（最多两轮，可配）→ 裁定 → 后端核验引用 → 分流（安全/卫生/健康类、置信度低于阈值、待人工 → 园长复核；其余成立项 → 整改单草稿）。同时保存"诊断员单独判断"和"对抗后裁定"两套结果。
3. 家园链（`parent_chain.py`）：调度官 + 关键词硬规则判断是否转人工 → 只检索公开知识起草 → 红队审查（低风险发送 / 中风险改写一次再审 / 高风险转教师）。
4. 议事链（`council_chain.py`）：四视角第一轮陈述 → 第二轮每方至少质疑一方 → 综合员简报（共识、保留的分歧、风险、备选方案）→ 园长记录决定。

### 步骤 8 复核、整改与工单时限

1. 复核队列只对园长（及按类别获授权的副园长）开放；复核结论作为标准答案。
2. 整改单按岗位规则建议责任人，**只有园长能确认下发**；责任人回传照片或说明，园长验收关闭。
3. 工单时限（`api/app/services/workorders.py`）：按校历工作时间计时，过半提醒，两级升级，可延期一次；规则在管理端配置，只对新建工单生效。

### 步骤 9 前端四个端与 3D 议事桌

1. 教职工端（手机）：三步提交、打码预览、对抗过程、申诉、整改回传、家长转人工、对话助手。
2. 园长端：驾驶舱（热力图、闭环率、对抗前后误判率、超时工单、家长统计、真实/演示数据切换）、复核与整改、园务议事、知识库。
3. 3D 议事桌（`web/src/scene/`）：通过 SSE（`/api/runs/{id}/stream`）实时接收发言，显示纸片人表情、发言气泡、质询/支持/引用光束、裁定托盘、置信度环；可回放。
4. 家长端：爱宝答疑；管理员端：初始化向导、导入中心、组织账号、学期任职轮换、作息课表、模型阈值、脱敏日志、时限规则、形象品牌。

### 步骤 10 测试与导出

1. 端到端冒烟测试：`api/tests/test_smoke.py`（覆盖项见《01_参赛内容介绍》第七节）。
2. 导出参赛代码包：`python scripts/export_package.py`，自动排除 `.env`、数据库、上传文件、依赖目录、含真实姓名的园方模板，并扫描密钥。

## 第二部分 部署与投入使用

### 步骤 1 准备服务器

- 最低：4 核 CPU / 8 GB 内存 / 50 GB 磁盘；推荐 8 核 / 16 GB / 100 GB SSD；无需 GPU。
- 系统：Ubuntu 22.04 / Debian 12 / CentOS Stream 9，Docker 24 以上。

### 步骤 2 配置环境变量

```bash
cp .env.example .env
```

在服务器上的 `.env` 中填写：

| 变量 | 说明 |
| --- | --- |
| `LLM_BASE_URL` / `LLM_API_KEY` | 通义千问 OpenAI 兼容接口地址与密钥（只放服务器，不进代码包） |
| `LLM_MODEL_FAST` / `LLM_MODEL_STRONG` | 默认 `qwen3.8-flash` / `qwen3.8-max` |
| `DB_PASSWORD`、`JWT_SECRET`、`CHILD_KEY` | 随机生成；`CHILD_KEY` 用于幼儿姓名加密，丢失后无法解密 |
| `REVIEW_CONFIDENCE_THRESHOLD` / `DEBATE_MAX_ROUNDS` / `FORCE_REVIEW_CATEGORIES` | 复核阈值 0.7、对抗轮数 2、强制复核类别"安全,卫生,健康" |
| `DEMO_MODE` / `SEED_DEMO` | **生产环境必须为 `false`** |

### 步骤 3 一键部署

```bash
bash deploy/install.sh
```

脚本检测 CPU、内存、磁盘和 Docker 版本；低于最低档时不启动本地语音识别（其他功能不受影响）。完成后由园方现有 HTTPS Nginx 反代到 8080 端口。

### 步骤 4 初始化（管理员端 → 初始化向导）

1. 下载导入模板，填写教职工名单、班级任职、校历周次（含值周负责人）、作息时段、特色课表，上传 → 查看校验报告 → 确认写入。
2. 下发初始密码文件给教职工（首次登录强制修改）。
3. 园长在园长端确认本学期班级任职表。
4. 上传园徽（自动生成各尺寸与主题色）与吉祥物形象。
5. 上传本园制度文件（内部）和家长须知、食谱、通知（公开）到知识库；上传后自动切片入库，可在知识库页面检索验证。
6. "模型与阈值"中做连通测试，按需为各智能体选择 max / flash，调整复核阈值与对抗轮数。
7. "时限规则"中核对各类工单的时限和升级对象。
8. 生成家长邀请码，发给试点班级家长。

### 步骤 5 试用与取证

1. 选 2–3 个班试用巡查链，园长每天处理复核队列（复核结论是计算误判率的标准答案）。
2. 驾驶舱切换到"真实数据"查看指标；演示数据（`is_demo`）不计入。
3. 导出或截图驾驶舱数据，作为《01_参赛内容介绍》第九节的成效证据。
