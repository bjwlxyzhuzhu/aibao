图 1 系统总体架构

flowchart TB
  subgraph Clients[四个终端（浏览器 / 手机网页）]
    S[教职工端<br/>三步巡查 · 申诉 · 整改回传]
    P[园长端<br/>驾驶舱 · 复核 · 3D 议事桌]
    F[家长端<br/>爱宝答疑]
    A[管理员端<br/>导入中心 · 知识库 · 模型与阈值 · 脱敏日志]
  end
  subgraph Server[园方服务器 · Docker Compose · HTTPS]
    WEB[web：Nginx 静态站点]
    API[api：FastAPI 业务层<br/>岗位+数据范围鉴权 · SSE 推送]
    subgraph Chains[智能体编排（自写）]
      C1[① 保教巡查链]
      C2[② 家园沟通链]
      C3[③ 园务议事链]
      OFF[离线规则引擎<br/>未配置模型/调用失败时兜底，界面标注]
    end
    SVC[业务服务<br/>校历单双周 · 在岗推算 · 工单时限与升级 · 导入与回滚]
    KB[知识库<br/>PDF/Word → 章·条切片 → 检索]
    DB[(PostgreSQL 16 + pgvector)]
    FS[文件存储<br/>原始件 / 打码件分目录]
    ASR[asr：本地语音识别<br/>SenseVoice-Small，音频不出园]
    GW[脱敏网关<br/>姓名→代号 · 号码住址→占位 · 健康明细→类别<br/>人脸模糊 · 去 EXIF · 失败即拒发 · 全量日志]
  end
  LLM[云端模型：通义千问<br/>qwen3.8-max / qwen3.8-flash<br/>OpenAI 兼容接口]
  S & P & F & A --> WEB --> API
  API --> C1 & C2 & C3
  API --> SVC
  C1 & C2 & C3 --> KB
  API --> ASR
  API --> FS
  API & SVC & KB --> DB
  C1 & C2 & C3 -->|所有模型调用| GW -->|只发脱敏文字和打码图片| LLM
  C1 & C2 & C3 -.->|降级| OFF

图 2 数据流与脱敏网关

flowchart LR
  IN[教师上传照片 / 语音 / 文字] --> IMG[本地人脸检测 YuNet<br/>高斯模糊全部人脸 · 去 EXIF]
  IN --> AU[本地语音转写<br/>音频留在园内]
  IMG --> PRE[打码预览<br/>教师确认后提交]
  AU --> TXT[文字]
  PRE --> GW
  TXT --> GW
  subgraph GW[脱敏网关 pass_through_gateway]
    T1[教职工姓名字典 → 教职工代号]
    T2[幼儿姓名 → 幼儿编号]
    T3[手机号 / 身份证 / 住址 → 占位符]
    T4[体温等健康明细 → 类别]
    T5[图片不在打码目录 → 拒发]
  end
  GW --> PL[RedactedPayload<br/>大模型客户端只接受此类型]
  GW --> LOG[(脱敏日志<br/>前后对比 · 替换项 · 仅管理员可见)]
  PL --> LLM[通义千问]
  LLM --> OUT[JSON 结果 → pydantic 校验]
  OUT --> RS[(结果入库：agent_messages · findings<br/>只含代号与岗位称呼)]

图 3 ① 保教巡查链工作流

flowchart TB
  A[教师三步提交巡查<br/>系统预选环节、带出在岗教师] --> B[脱敏网关]
  B --> C[知识库检索前 8 条相关条款]
  C --> D[巡查诊断员 星宝<br/>输出问题清单 findings<br/>每条须引用切片]
  D -->|无问题| Z[记录完成]
  D --> E[一线质询员 护苗<br/>逐条：反驳 / 同意 / 补充情境]
  E -->|有反驳且轮数 ≥ 2| F[诊断员答辩<br/>坚持 / 撤回，只回应一次]
  E -->|无反驳| G
  F --> G[条款裁判员 明理<br/>成立 / 不成立 / 待人工 + 置信度]
  G --> H{后端核验<br/>引用切片是否真实存在}
  H -->|不存在| HR[强制改为「待人工」]
  H -->|存在| I{分流}
  HR --> I
  I -->|待人工、置信度 < 0.7、<br/>或安全/卫生/健康类| R[园长复核队列<br/>（复核工单计时）]
  I -->|成立且无需复核| K[整改跟踪员 小步<br/>起草整改单 · 按岗位建议责任人]
  I -->|不成立| Z
  R -->|园长判定成立| K2[按模板生成整改单草稿<br/>附园长复核意见] --> L
  R -->|园长判定不成立| Z
  K --> L[园长确认 / 修改后下发<br/>（非园长无法下发）]
  L --> M[责任人限时整改并回传照片或说明]
  M --> N[园长验收关闭]
  E2[教师申诉] -.-> R
  G -.->|两套结果入库| S[(诊断员单独判断 vs 对抗后裁定<br/>以园长复核为标准答案计算误判率)]

图 4 ② 家园沟通链工作流

flowchart TB
  Q[家长提问] --> D{调度官 爱宝<br/>+ 关键词硬规则}
  D -->|涉及具体孩子、请假、受伤、<br/>身体不适、投诉、费用| TR[转班级教师<br/>爱宝回复「已转给老师」<br/>生成家长工单（2 工作小时）]
  D -->|公开知识类| K[只检索公开知识库<br/>作息 · 食谱 · 须知 · 通知]
  K --> A[爱宝答疑员起草<br/>80 字内 · 标注来源]
  A --> R[风险审查员 小卫士（红队）<br/>隐私 · 越权承诺 · 医疗建议 · 情绪 · 事实]
  R -->|低风险| SEND[发送给家长]
  R -->|中风险（第一次）| RW[按审查意见改写一次] --> R
  R -->|高风险 / 改写后仍非低风险| BLK[拦截草稿 → 转班级教师]
  TR & BLK --> T[教师在教职工端回复]
  SEND & BLK & TR --> ST[(驾驶舱统计：自动答复率 · 拦截数 · 转人工数 · 高频问题)]

图 5 ③ 园务议事链工作流

flowchart TB
  T[园长 / 副园长提出议题<br/>文字或语音，可附文件] --> R1
  subgraph R1[第一轮 陈述]
    H1[保健 小医] 
    T1[教师 小师]
    P1[家长 小家]
    S1[安全 小盾]
  end
  R1 --> R2
  subgraph R2[第二轮 交叉质询：每方至少质疑一方]
    H2[保健] --> X1[质疑对象]
    T2[教师] --> X2[质疑对象]
    P2[家长] --> X3[质疑对象]
    S2[安全] --> X4[质疑对象]
  end
  R2 --> B[决策综合员 爱宝<br/>共识 · 保留的分歧（写明双方与分歧点）· 风险 · 2–3 个备选方案]
  B --> D[园长记录最终决定 → 归档]

图 6 工单时限与两级升级

flowchart LR
  N[工单创建<br/>复核 / 整改 / 验收 / 申诉 / 家长转人工] --> H[时限过半或到期前<br/>提醒责任人]
  H -->|按时完成| D[完成，计入按时完成率]
  H -->|超时| E1[第一级：责任人 + 班长或部门负责人 + 副班长]
  E1 -->|仍未完成| E2[第二级：分管副园长 + 园长<br/>驾驶舱标红]
  E1 & E2 --> R[(时间线与汇总)]
  H -.->|申请延期一次，园长批准后重新计时| N

图 7 3D 议事桌数据驱动

sequenceDiagram
  participant Chain as 智能体链路
  participant DB as agent_messages
  participant API as /runs/{id}/stream (SSE)
  participant UI as 3D 议事桌
  Chain->>DB: 每一轮发言（agent, action, target, cited, confidence, emotion）
  API->>DB: 轮询新发言
  API-->>UI: SSE 推送
  UI->>UI: 纸片人表情 · 发言气泡 · 质询/支持/引用光束 · 裁定托盘 · 置信度环
  UI->>API: 回放：GET /runs/{id} 取全部发言按序重播
